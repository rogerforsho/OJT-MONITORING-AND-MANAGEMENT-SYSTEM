# Implementation Plan
	
Do not build the entire web app and then rebuild the entire mobile app. Build shared foundations, then complete vertical feature slices.

## Phase 0 — Baseline
Resolve blocking contradictions and approve Version 1.0.

## Phase 1 — Foundation
Repository, environments, Supabase connection, authentication foundation, role model, error conventions.

## Phase 2 — Accounts and Approval
Student registration → pending state → Coordinator approval/rejection → Admin technical account status → sign in/out → password reset.

## Phase 3 — Companies and Assignments
Company records → supervisor association → student/company assignment → student/supervisor assignment → assignment authorization.

## Phase 4 — Attendance
Data model → schedule dependency → QR issuance/validation → mobile scanning → selfie capture/storage → Time In/Out → supervisor verification → credited-hour calculation → offline pending capture → synchronization/conflict handling → tests.


## Phase 5 — Progress
Calculate from valid credited attendance. Clients cannot directly set completed hours.

## Phase 6 — Reports
First finalize report types, files, limits, deadlines, statuses, and review rules; then implement.

## Phase 7 — Evaluations
First finalize institutional evaluation form; then implement.

## Phase 8 — Notifications
Implement only approved events and permissions. No private chat unless approved.

## Phase 9 — Program Head Monitoring
Implement approved metrics from real data only.

## Phase 10 — Hardening
Permissions, ownership, cross-platform consistency, offline sync, file access, selfie access, errors, responsiveness.

A feature is complete only when acceptance criteria and required tests pass.

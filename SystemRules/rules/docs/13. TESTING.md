# Test Plan

## Critical Scenarios

### Registration
- Student registers and becomes pending.
- Pending student cannot access protected OJT functions.
- Coordinator can approve/reject.
- Admin cannot replace Coordinator academic approval authority.

### Authorization
- Student cannot access another student's private records.
- Supervisor cannot access unassigned students' restricted records.
- Unauthorized roles cannot perform Coordinator/Admin actions.

### Attendance
- Valid Time In follows approved workflow.
- Invalid/expired QR does not create valid attendance.
- Required selfie evidence is protected.
- Time Out completes the session.
- Invalid/rejected attendance is not credited.
- Late status uses approved schedule data.
- Weekend attendance is rejected in Version 1.0.
- Offline capture is visibly pending.
- Sync does not silently overwrite conflicts.

### Progress
- Credited hours derive from valid attendance.
- Remaining hours derive from approved required hours.
- Client cannot arbitrarily set completed hours.

### Reports
- Approved submission workflow works.
- Unauthorized file access fails.
- Status changes follow permissions.

### Evaluation
- Supervisor evaluates only assigned students.
- Fields match approved institutional form.

### Cross-Platform
- Same canonical data appears after synchronization.
- UI differences do not change authorization rules.

## Security
Test unauthenticated access, role escalation, direct-object access, sensitive file access, exposed secrets, expired QR, and duplicate sync.

Never report “passed” unless tests were actually executed and observed.

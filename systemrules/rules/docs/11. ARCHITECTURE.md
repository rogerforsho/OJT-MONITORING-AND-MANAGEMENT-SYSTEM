# System Architecture

## Technology Stack (Per Capstone Manuscript)
- **Web Application:** Next.js (App Router) + TypeScript + Tailwind CSS
- **Mobile Application:** React Native + Expo (Expo Go testing) + TypeScript + NativeWind
- **Backend & Database:** Supabase (PostgreSQL, Supabase Auth, Private Storage, Row Level Security)
- **Design & Prototyping:** Figma
- **Version Control & Collaboration:** GitHub
- **IDE:** Visual Studio Code

*Do not replace these technologies unless explicitly instructed.*

## Coordinator–Supervisor Chat
- Chat is an online-only, web-only feature built with the existing Next.js App Router and Supabase stack.
- PostgreSQL stores one conversation per eligible Coordinator–Supervisor pair and immutable text messages. RLS is the authoritative boundary for conversation, message, read-marker, and notification access.
- Eligibility is derived from active account roles, the Coordinator’s department, and the course department of a Supervisor’s active trainee placement. Sending is allowed only while at least one such placement exists; prior history stays readable after eligibility ends.
- Supabase Realtime publishes new chat-message rows to authorized participants. The browser subscribes only to the open conversation and removes the subscription when it closes.
- Each new message creates a generic notification linked to its conversation. Coordinator/Supervisor inbox and bell badge use the shared notifications table; notification text never includes the message body.
- Admin and Program Head routes and data access do not include chat privileges.

## Architectural Rules
1. **Single Source of Truth:** Centralized Supabase database is the sole authoritative store.
2. **Online-First Operational Model:** The system requires an active internet connection as specified by the manuscript.
3. **Defense in Depth:** Every table enforces strict RLS policies; API services perform server-side assertion checks (`assertCoordinator`, `getAuthUserWithRole`).
4. **Signed Asset Security:** Attendance selfie evidence and report documents use short-lived signed URLs.
5. **8 GB RAM Constraint Optimization:** Cloud-hosted backend infrastructure avoids heavy local database containers, keeping the dev environment fast and lightweight on minimum hardware specifications (i5/Ryzen 5, 8GB RAM).

# Workflows

## Student Registration
1. Student submits registration and student identity information.
2. System creates a pending account.
3. Coordinator verifies legitimacy.
4. Coordinator approves or rejects.
5. Approved account gains authorized student access.

## Assignment
1. Coordinator creates/selects company.
2. Coordinator creates/selects supervisor through approved account procedure.
3. Coordinator assigns student to company.
4. Coordinator assigns supervisor to student.
5. Assignment controls supervisor access.

## Online Attendance
1. Student signs in on mobile.
2. Student starts Time In.
4. Student captures Time In selfie.
5. System records the event and verification state.
6. Student later performs Time Out with required attendance evidence.
7. Supervisor manually reviews required selfie evidence.
8. Only valid attendance is credited.
9. Progress is recalculated from credited attendance.

## Offline Attendance Synchronization
1. App detects no connectivity.
2. Permitted attendance evidence is captured locally.
3. Event is marked pending synchronization with original capture time.
4. When connectivity returns, app submits the event.
5. Server validates it.
6. Accepted event becomes canonical; rejected/conflicting event shows the server result.

## Report Submission
1. Student views an approved requirement.
2. Student submits the required file/data.
3. System validates approved constraints.
4. Submission is stored with status.
5. Coordinator reviews according to institutional process.
6. Student sees authorized status/remarks.

## Evaluation
1. Supervisor opens an assigned student.
2. Supervisor completes the approved institutional evaluation form.
3. System validates required fields.
4. Evaluation is stored and shown only to authorized roles.

## Notification
Approved event or announcement → determine authorized recipients → store notification → recipient views notification.

## Admin
Admin performs only authorized technical account/access operations; academic decisions remain with academic roles.
